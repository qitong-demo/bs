## 二、写入路径并发正确性

| 校验项 | 预期 | 实测 | 结论 |
| --- | --- | --- | --- |
| 同一用户并发报名同一活动 | 仅 1 次成功 | 成功 1，被拒 7 | 通过 |
| 并发提交预约 | 全部成功且编号唯一 | 成功 8，唯一编号 8 | 通过 |
| 并发审核同一预约 | 仅 1 次成功 | 成功 1，被拒 7 | 通过 |
| 并发办结同一诉求 | 仅 1 次成功 | 成功 1，被拒 7 | 通过 |

并发正确性依赖以下实现约束：

- 活动报名：报名前对 `activity` 行加 `SELECT ... FOR UPDATE` 行锁，把同一活动的并发报名串行化；`activity_signup` 表对 `(activity_id, user_id)` 建唯一索引，并将数据库唯一约束冲突转换为 400 中文提示。
- 预约审核与取消：使用带状态条件的 `UPDATE ... WHERE status = ?` 条件更新并检查影响行数，只有仍处于待确认状态的记录会被修改，并发下只成功一次。
- 诉求分派与办结：同样使用带状态条件的条件更新，只有未办结 / 未关闭的诉求可以被处理，保证每个状态变更只留一条处理记录。
- 内存演示实现：对应的写操作使用 `synchronized` 串行化，保证演示模式下行为一致。

## 三、测试期间产生的数据

| 数据 | 说明 |
| --- | --- |
| 预约记录 | 并发正确性检查会写入若干条测试预约，沟通事项由脚本生成 |
| 测试活动 | 每次运行创建 1 个「并发报名测试活动」用于验证报名互斥（本次 id=8） |
| 测试诉求 | 每次运行创建 1 条「并发测试诉求」用于验证办结互斥 |
| 活动报名 | 针对上述测试活动产生 1 条有效报名记录 |

这些数据仅用于测试，可在重新执行 `scripts/init-mysql.ps1 -Reset` 后清空。

## 四、结论与局限

在本地演示数据规模下，只读接口未出现失败请求，写入路径的并发互斥符合预期。

尚未覆盖的内容：

- 未做长时间稳定性与内存泄漏测试；
- 未做多实例部署下的分布式并发测试（当前为单实例）；
- 未与生产环境 SLO 指标对标，也未使用专业压测工具（如 JMeter、wrk）做阶梯加压；
- 演示数据量远小于真实业务规模，索引与查询计划未在真实数据量下验证。

## 五、复现方式

```powershell
# 1. 启动后端（MySQL 模式，需先执行 scripts/init-mysql.ps1）
cd backend
java -jar target/platform-0.0.1-SNAPSHOT.jar --spring.profiles.active=mysql

# 2. 运行性能与并发测试
node scripts/perf-test.mjs --requests 60 --concurrency 10
```
